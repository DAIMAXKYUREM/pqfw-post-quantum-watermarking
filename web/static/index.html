Post-quantum forensic watermarking

Real cryptography, server-side. NIST-standardised post-quantum primitives throughout — ML-KEM-768 (FIPS 203) for key encapsulation and ML-DSA-65 (FIPS 204) for the digital signature that binds each decryption to its recipient, giving non-repudiation: the record is signed with the recipient's own private key, so they cannot later deny having decrypted the file. Content and slot variants use AES-256-GCM; hashing, commitments and Merkle roots use SHA3-256. Nothing on this page is pre-computed.

Immutable audit layer. Signed decryption records are committed to a permissioned distributed ledger: three independent validator nodes, each holding its own replica, each re-verifying every receipt, committing blocks at a 2-of-3 quorum. No single administrator or compromised account can retroactively alter or erase a record — step 5 runs that attack live. Fully offline and air-gapped: no cloud KMS, no public blockchain, no external network call at any point. A test that replaces the socket layer with one refusing every operation runs the whole pipeline anyway.

Known limits, stated deliberately. The text carrier does not survive whitespace normalisation, retyping, OCR, or an inserted word — the threat model is redistribution of the file, not manual reconstruction. The distributor knows every codeword, so the guarantee is traceability, not unframeability. When an attack wins, the result is a failure to identify — never the wrong person.
